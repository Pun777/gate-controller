# Gate Controller (WT32-ETH01): ติดตั้งและอัปเดตด้วยปุ่มเดียว

ระบบนี้มี 2 ทางให้ลงโปรแกรมไม้กั้นบนบอร์ด WT32-ETH01

| | ใช้เมื่อไหร่ | ผู้ใช้ทำอะไร |
|---|---|---|
| **ติดตั้งผ่านสาย USB** | บอร์ดใหม่ ครั้งแรกครั้งเดียว | เปิดหน้าติดตั้ง ต่อสาย แล้วกด **ติดตั้งลงบอร์ด** |
| **อัปเดตผ่าน LAN** | ทุกครั้งหลังจากนั้น | เปิดหน้าเว็บของบอร์ด แล้วกด **อัปเดตโปรแกรม** |

ทั้งสองทางเก็บค่า IP / Gateway / Subnet / DNS ที่ตั้งไว้ในบอร์ดไว้ครบ

## Gate Controller IDE (หน้าเว็บแบบ Arduino IDE)

เปิด `https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/` ด้วย Chrome หรือ Edge

| ส่วน | ใช้ทำอะไร |
|---|---|
| **✓ คอมไพล์** (Ctrl+S) | บันทึกโค้ดขึ้น GitHub แล้วคอมไพล์ ถ้ามี error จะไฮไลต์บรรทัดที่ผิดในตัวแก้โค้ด (ราว 2–5 นาที) |
| **→ อัปโหลด** (Ctrl+U) | ลงโปรแกรมที่คอมไพล์ล่าสุดผ่านสาย USB |
| **บอร์ด / พอร์ต** | เลือกชิปและตัวแปลง USB ที่ต่ออยู่ |
| **Serial Monitor** | ดูข้อความจากบอร์ด เลือก baud ได้ ส่งข้อความกลับได้ และแสดงลิงก์ IP ให้เมื่อบอร์ดรายงาน |
| **เชื่อมต่อ GitHub** | วาง Personal access token (Contents: Read and write, Actions: Read-only) เพื่อแก้โค้ดบนเว็บ ไม่ใส่ก็เปิดอ่านและอัปโหลดได้ |

### รัน IDE พร้อมเซิร์ฟเวอร์คอมไพล์ในเครื่อง (Docker)

คอมไพล์ในเครื่อง 7–30 วินาที ไม่ต้องใช้ GitHub token และมีปุ่ม **✓ ตรวจโค้ด** (Ctrl+R) กับ **→ อัปโหลด** (Ctrl+U คอมไพล์ บันทึก แล้วลงบอร์ด) เหมือน Arduino IDE

ต้องมี Docker Desktop (ใช้ WSL 2) พื้นที่ว่างราว 8 GB และ RAM 4 GB ขึ้นไป

เปิด (ครั้งแรกใช้เวลา build ราว 10–15 นาที):

```bash
docker compose up -d --build
```

แล้วเปิด http://localhost:8080 ด้วย Chrome หรือ Edge

หยุด:

```bash
docker compose down
```

- โค้ดที่บันทึก ประวัติทุกเวอร์ชัน และไฟล์โปรแกรม เก็บใน Docker volume `ide-data` ปิดเปิดเครื่องแล้วไม่หาย
- เปิดได้จากเครื่องนี้เครื่องเดียว (127.0.0.1) เพราะการลงบอร์ดผ่าน USB บนเบราว์เซอร์ใช้ได้เฉพาะ `localhost` หรือ HTTPS
- ตั้งรหัสผ่านได้ที่ `IDE_PASSWORD` ใน `docker-compose.yml` (ชื่อผู้ใช้ `admin`)
- โปรแกรมที่คอมไพล์ในเครื่องปิดการอัปเดตผ่าน LAN ไว้ (`UPDATE_BASE` ว่าง) จนกว่าจะย้ายเซิร์ฟเวอร์ขึ้นโดเมนที่มี HTTPS
- ทดสอบเซิร์ฟเวอร์ทั้งระบบได้ด้วยคำสั่งด้านล่าง

```bash
python server/selftest.py http://localhost:8080
```

### ติดตั้งบนเซิร์ฟเวอร์ในวง LAN (HTTPS + รหัสผ่าน)

```bash
git clone https://github.com/Pun777/gate-controller.git /home/bgs/docker-compose-buildboard-venus
```

```bash
cd /home/bgs/docker-compose-buildboard-venus && cp deploy/.env.example .env && nano .env
```

```bash
docker compose -f docker-compose.server.yml up -d --build
```

- เปิด `https://<SERVER_ADDR>:8843` ผู้ใช้ `admin` รหัสผ่านตาม `IDE_PASSWORD` ใน `.env`
- HTTPS ใช้ใบรับรองของ Caddy เอง ติดตั้งใบรับรอง root ในเครื่องที่ใช้งานครั้งเดียว (ดึงได้ด้วยคำสั่งด้านล่าง) แล้วเบราว์เซอร์จะไม่เตือนอีก

```bash
docker compose -f docker-compose.server.yml exec -T https cat /data/caddy/pki/authorities/local/root.crt > gate-ide-root-ca.crt
```

- อัปเดตเป็นโค้ดล่าสุดจาก GitHub: `git pull && docker compose -f docker-compose.server.yml up -d --build`
- IDE ถูกจำกัด RAM 2 GB / CPU 2 คอร์ เพื่อไม่ให้กระทบบริการอื่นบนเครื่อง

### ระบบกันบอร์ดพัง
- **เช็กลิสต์ก่อนอัปโหลด** ทุกครั้ง: ไฟ 5V เท่านั้น ห้าม 12V, ใช้ไฟแยกต้องถอด VCC ของตัวแปลงและต่อ GND ร่วม
- **ตรวจบอร์ดก่อนเขียน:** ฟังสัญญาณจากบอร์ดแล้วบอกสาเหตุเป็นภาษาไทย เช่น ไฟไม่พอ (รีเซ็ตวน), สาย TX/RX แตะกัน, ยังไม่เข้าโหมดรับโปรแกรม และรอจนบอร์ดพร้อมแล้วค่อยเขียน ไม่เขียนทั้งที่ไฟไม่พอ
- **ตรวจชิป:** ถ้าชิปที่ต่อไม่ตรงกับบอร์ดที่เลือก จะไม่เขียน
- **ตรวจ MD5 หลังเขียน** ทุกส่วน ถ้าไม่ตรงจะแจ้งให้เขียนใหม่
- **ไม่ลบค่า IP** ที่บันทึกในบอร์ด
- **อัปเดตผ่าน LAN แล้วย้อนกลับเองได้:** เวอร์ชันใหม่ต้องต่อ LAN ได้และทำงานต่อเนื่อง 30 วินาที ถ้าค้าง รีบูตวน หรือต่อ LAN ไม่ได้ใน 3 นาที บอร์ดจะกลับไปใช้เวอร์ชันเดิมเอง
- **แจ้งไฟตก:** หน้าเว็บของบอร์ดและ Serial Monitor แสดงเมื่อบอร์ดรีสตาร์ทเพราะไฟตก

ระบบนี้กันพังจากซอฟต์แวร์และจากการเขียนโปรแกรมผิดจังหวะได้ แต่**กันความเสียหายทางไฟฟ้าไม่ได้** เช่น ต่อ 12V เข้าขา 5V หรือสลับขั้ว ต้องเช็กสายไฟก่อนเสียบทุกครั้ง

## ตั้งค่าครั้งแรก (ผู้ดูแล ทำครั้งเดียว)

1. สร้าง repository บน GitHub แล้วอัปโหลดทุกไฟล์ในโฟลเดอร์นี้ รวมโฟลเดอร์ `.github`
2. ไปที่ **Settings → Pages → Build and deployment → Source** แล้วเลือก **GitHub Actions**
3. push ขึ้น branch `main` แล้วรอ 3–6 นาที ดูความคืบหน้าได้ที่แท็บ **Actions**
4. ได้ลิงก์หน้าติดตั้ง `https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/`

ที่อยู่สำหรับอัปเดตผ่าน LAN ถูกใส่ลงโปรแกรมให้อัตโนมัติจากชื่อ repo
ถ้าใช้โดเมนของตัวเอง ให้ใส่ใน `project.json` ช่อง `"updateUrl"` เช่น `"https://gate.example.com/"`

## ลงบอร์ดใหม่ครั้งแรก (ผ่านสาย USB)

WT32-ETH01 ไม่มีช่อง USB ต้องใช้ตัวแปลง USB-TTL (CH340, CP2102 หรือ FTDI)

| ตัวแปลง USB-TTL | WT32-ETH01 |
|---|---|
| TX | RX0 |
| RX | TX0 |
| GND | GND |
| 5V | 5V |

1. ต่อขา **IO0 ลง GND** แล้วถอดไฟ-เสียบไฟใหม่ บอร์ดจะเข้าโหมดรับโปรแกรม
   (ถ้าใช้บอร์ดโหลดแบบ auto-reset เช่น ESP-Prog ข้ามข้อนี้ได้)
2. เปิดหน้าติดตั้งด้วย Chrome หรือ Edge บนคอมพิวเตอร์ แล้วกด **ติดตั้งลงบอร์ด** และเลือกพอร์ต
3. เสร็จแล้วถอด IO0 ออกจาก GND และถอดไฟ-เสียบใหม่
4. เสียบสาย LAN หน้าติดตั้งจะแสดง IP ของบอร์ดให้กดเปิดหน้าควบคุมได้เลย

## อัปเดตโปรแกรมผ่าน LAN

1. แก้โค้ดใน `firmware/firmware.ino` แล้ว push รอ GitHub Actions เสร็จ
2. เปิดหน้าเว็บของบอร์ด (`http://<IP บอร์ด>/`) แล้วกด **อัปเดตโปรแกรม**
3. รอประมาณ 1 นาที หน้าเว็บจะแจ้งเมื่อเสร็จ

สิ่งที่ต้องรู้:
- วง LAN ต้องออกอินเทอร์เน็ตได้ ถ้าใช้ Static IP ต้องตั้ง **DNS** ด้วย (ค่าเริ่มต้น `8.8.8.8`)
- ระหว่างอัปเดต บอร์ด**สั่งไม้กั้นลงก่อน** และรับคำสั่ง `/on` ไม่ได้ประมาณ 1 นาที ควรอัปเดตช่วงที่ไม่มีรถ
- บอร์ดดาวน์โหลดได้เฉพาะจากที่อยู่ที่ฝังไว้ในโปรแกรม ผ่าน HTTPS ที่ตรวจใบรับรองแล้ว
  ใครกดปุ่มอัปเดตก็ได้แค่โปรแกรมเวอร์ชันล่าสุดของคุณเอง ลงโปรแกรมอื่นแทนไม่ได้
- โปรแกรมที่คอมไพล์จาก Arduino IDE ตรงๆ (ไม่ผ่าน build นี้) จะแสดง Firmware เป็น `dev` และปิดปุ่มอัปเดตไว้

## โครงสร้างไฟล์

| ไฟล์ | หน้าที่ |

## ข้อควรระวัง

- GitHub Pages แบบฟรีต้องใช้ repo สาธารณะ ใครก็ดาวน์โหลดไฟล์โปรแกรมได้ **ห้ามใส่รหัสผ่านหรือข้อมูลลับในโค้ด**
- `project.json` ล็อกคอร์ ESP32 ไว้ที่ `"3.3.12"` ซึ่งคอมไพล์ผ่านแล้ว (ใช้พื้นที่ 59% ของช่องโปรแกรม)
  เปลี่ยนเป็น `"latest"` ได้ถ้าต้องการคอร์ใหม่สุด โค้ดนี้ต้องใช้คอร์ 3.x ขึ้นไป
- GPIO15 (RELAY_UP) เป็นขา strapping ของ ESP32 จะถูกดึงเป็น HIGH ช่วงบอร์ดบูต
  รีเลย์ยกไม้กั้นอาจทำงานแวบหนึ่งทุกครั้งที่บอร์ดรีสตาร์ท (รวมตอนอัปเดตและตอน Save & Reboot) ควรทดสอบกับไม้กั้นจริง
- ถ้า GitHub เปลี่ยนผู้ออกใบรับรองไปรายที่ไม่มีใน `ca_roots.h` บอร์ดจะอัปเดตผ่าน LAN ไม่ได้
  แก้โดยเพิ่ม root ใหม่ใน `ca_roots.h` แล้วลงผ่าน USB หนึ่งครั้ง
